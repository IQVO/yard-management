The WMS-tier owner of everything physically on site outside the four walls (ADR 0001, ADR 0002): visits through the gate (YardVisit), the trailers on site and where each is (Trailer), the moves hostlers and visiting drivers make (YardMove), yard checks (YardCheck) and the per-site yard rules (YardPolicy). It is the source of dwell, door occupancy and yard truck productivity facts.

A trailer on site is at exactly one place: one yard spot, one door, or one open move. A spot or a door holds at most one trailer. Moves are pulled by hostlers (claim-next with a lease), never pushed. Appointments, door closures, locations and ASN contents come from event-fed local copies (ADR 0003); this API never calls a sibling context. Events are published as CloudEvents on `warehouse.yard-management.events` and `.analytics` through a transactional outbox (see `apis/asyncapi.yaml`).

Sites are addressed by siteCode and doors and spots by their facility-layout locationCode (globally unique). Errors are RFC 7807 problem documents with `type = https://errors.yard-management.warehouse-systems.dev/<slug>`, the slug being the kebab-case of the domain error name (`ErrLocationOccupied` is `location-occupied`). There is no authentication layer (fleet decision 2026-09-11).
